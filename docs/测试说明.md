# 测试说明

## 怎么跑

```bash
npm test              # 单元测试，52 项通过，不需要网络与凭证
SMOKE=1 npm test      # 追加真实数据联调，8 项，需要 .env.local 里的两个 Key
```

单元测试全部是纯函数，跑一次约 1 秒；联调测试会真实请求扶摇与 iFinD，约 20 秒。

`npm test` 会经由 `scripts/run-tests.mjs` 把 TEMP/TMP 指到项目内 `.tmp/` 再启动 Vitest
（原因见第五节），并关闭文件级并行 —— 否则在受限环境下会出现「测试文件被静默漏收」的假绿。

## 二、数据缺失与接口失败

| # | 场景 | 期望行为 | 覆盖方式 |
|---|---|---|---|
| 1 | 没配 `FUYAO_API_KEY` | 抛 `MissingCredentialError`，页面显示缺失原因，不伪造数据 | `providers/types.ts` |
| 2 | API Key 无效 | 扶摇返回 `code=2003`，转成 `ProviderError` 并提示「无权限」 | 实测：`{"code":2003,"message":"Invalid or revoked API key"}` |
| 3 | 触发限流 | `code=4001` → 错误信息附带「降低并发、不要立即重试」提示 | `providers/fuyao.ts` |
| 4 | 缺参数 / 参数格式错 | `code=1001` / `code=1002` 原样透传到 gaps | 实测：`date must be yyyy-MM-dd` |
| 5 | 交易日历覆盖不到区间 | 抛 `CalendarCoverageError`，**不回退自然日** | `tests/time-calendar.test.ts` 2 项 |
| 6 | 空白日历 | 同样抛错，不返回 0 | 同上 |
| 7 | iFinD 板块收益解析失败 | `value=null` + gap 登记，`sectorPct` 记 0 并标注降级，**不猜数不置 0 冒充「行业无贡献」** | `providers/ifind.ts` |
| 8 | iFinD 请求超时 | 45 秒超时抛 `ProviderError`，不是无限等待 | `providers/ifind.ts` |
| 9 | 公告只有日期没有时间 | 标 B 级 + `date` 精度，同日判 `uncertain` | `tests/timewall.test.ts` |
| 10 | 同指标多源冲突 | 两方都保留、互指 `conflictWith`、界面提示「以原文口径判断」 | `tests/evidence.test.ts` 5 项 |

真实冲突夹具（不是构造的，是 2026-10-25 实测到的）：

```
GET .../limit-up-pool?date=2026-10-16        → total: 0
GET .../limit-up-statistics?date=2026-10-16  → limit_up_stock_count: 59
```

产品不选一个更好看的数字用，而是把两条都放进证据集并互相标记冲突。

## 三、极端与合规边界

| # | 场景 | 期望行为 | 覆盖方式 |
|---|---|---|---|
| 1 | 归因入口混入事后证据 | 直接抛 `TimeWallViolation`，不是静默计算 | `tests/review.smoke.test.ts` |
| 2 | 出口混入事后证据 | `guardNoFutureLeak` 抛错并列出违规条目 | `tests/timewall.test.ts` 2 项 |
| 3 | 发布时间恰等于决策时点 | 判为可见（`≤` 而非 `<`） | `tests/timewall.test.ts` |
| 4 | 标记 ms 精度但字段缺失 | 保守判 `unknown_time`，不猜 | 同上 |
| 5 | 证伪条件为空 | 表单拒绝提交；已存在的空台账被 `no_falsify_condition` 规则命中 | `api/hypothesis` + `tests/review.smoke` |
| 6 | 样本不足 | `lowSample=true`，只报「样本不足」不下结论 | `bias.ts` |
| 7 | 未平仓 | 不计算归因，返回「该笔尚未卖出」的 gap | `review.ts` |
| 8 | 合规文案 | 全站无涨跌预测 / 收益承诺 / 买卖建议；结论只对照「你自己写下的规则」 | 人工审查，见下 |

合规审查口径：**不说「你当时应该止损」，改说「你写下的证伪条件是 X，它在 T+n 触发，若按此执行结果会是 Y」**。
所有页面底部都有声明，所有数字都可以点开「溯源」看到来源接口与原始字段。

## 四、手工验收清单

```bash
npm run dev
```

1. 打开 `/` —— 三笔持仓，收益列标注为「价格涨跌」（未含费用，与复盘页含费用口径区分）
2. 打开 `/review/T1?viewpoint=entry` —— 时间线只到 08-03 10:23；当日收盘 K 线在「后视镜区」；顶部有决策日空白说明
3. 切换 `viewpoint=today` —— 后视镜区仍有内容，但「当时可见的证据」不变
4. 展开任意证据的「溯源」 —— 能看到判定理由、统计口径与原始字段 JSON
5. 展开「收益归因」下方 —— β、样本交易日数、板块收益均可见
6. `/hypothesis/T1` —— 证伪条件留空点保存，必须被拒绝
7. `/import` —— 点「填入示例数据」→ 解析预览 → 字段映射与逐行错误可见 → 确认导入
8. 断网或改错 Key 再访问复盘页 —— 缺口区列出失败项，页面不崩、不显示「正常」
9. 在复盘页点「存入我的清单」→ 打开 `/patterns` 看偏差频次是否聚合了多笔
10. 打开 `/plan`，输入「长鑫科技」+ 板块「半导体」→ 应匹配出同标的与通用清单项，每条带匹配理由
11. 不勾完所有项时「确认建仓」按钮应为禁用态 —— 强制确认是回灌的关键，不能只做展示
12. 打开 `/review/T1?viewpoint=entry` —— 决策时点位置应出现一条虚线边框的「没有盘面数据」系统说明条目
13. 打开 `/decisions` —— 应看到一条「待回检」决策，自动事实含决策价、至今涨跌、最大回撤、经过交易日、证伪阈值（已触及）
14. 选择「没有执行」+ 填一句备注 → 提交 → 顶部「已回检 1/1」「清单完全执行率 0%」应随之更新
15. 证伪条件写成「低于 20 日均线减仓」再回检 —— 阈值应显示「—」并提示没有可解析的价格阈值，不得把 20 当成价位
16. 首页「今日待办」应列出待回检决策与未写台账的持仓，点击可直达
17. `/patterns` 的「偏差趋势」应有三条带「演示」标记的历史快照，点「保存本次快照」后追加一条真实快照（无演示标记）
18. `/plan` 在资产为空时应提供「从我的复盘生成清单」，点击后生成真实偏差对应的条目（不是伪造清单）

## 五、环境注意事项（排查记录）

**1. `next build` 报 `EPERM: open '.next/trace'`**
不是路径问题（英文路径同样复现）、不是 `NODE_OPTIONS`、不是沙箱。
真因是**还有 dev server 进程存活，占着 `.next` 目录的文件句柄**，Next 清理临时目录时被拦。
排查方式：`Get-Process node` 看有没有残留 → 全部结束后重跑，一次通过。
若在别的机器上遇到同样报错，先查这个，别急着改配置。

**2. 某些沙箱环境里 dev server 启动即崩**
日志里出现 `[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED]` 时，
说明所在环境对批量删除做了拦截，可用 `CODEBUDDY_SAFE_DELETE_ENABLED=0 next dev` 绕过。
这是宿主环境行为，与产品代码无关。

**3. Vitest 偶发「测试文件变少」的假绿**
宿主环境的文件系统 shim 会拦截 Vitest 写系统临时目录，抛 `EPERM`。
后果不是报错退出，而是**部分测试文件被漏收** —— 表现为「37 passed」突然变成「22 passed」，很容易误判成通过。
已修：`scripts/run-tests.mjs` 把 TEMP/TMP/TMPDIR 指向项目内 `.tmp/`，同时 `fileParallelism: false`。
修复前 3 次运行会出现 1 次漏收，修复后连续 3 次结果完全一致（52 passed / 8 skipped）。

**4. 端口占用**
默认 3100（避开常见的 3000）。改端口：`next dev -p 3200`。
