# 复盘 · 投资决策留痕

> 投资者通常只记得盈亏，却很难还原当时的信息、假设、行为和后续变化。
> 这个产品做的事：把成交记录、当时可见的市场信息、你写下的假设对齐到一条时间线，
> **先拦住事后才知道的信息**，再拆开收益里哪部分来自市场、哪部分来自你的判断。

---

## 快速开始

```bash
# 1. 依赖
npm install

# 2. 环境变量（复制模板后填入自己的 Key，切勿提交）
cp .env.example .env.local
#   FUYAO_API_KEY=...      扶摇金融数据 API，https://fuyao.aicubes.cn/admin/ 签发
#   IFIND_AUTH_TOKEN=...   iFinD MCP，https://mcp.51ifind.com 个人中心获取

# 3. 启动
npm run dev        # http://localhost:3100
npm test           # 单元测试（不需要网络与凭证）
SMOKE=1 npm test   # 追加真实数据联调（需要凭证）
npm run build && npm start
```

没有凭证也能启动：页面能开，但所有取数会走「显式缺口」路径，
界面会显示缺失原因而不是伪造数据。

## 目标用户与核心场景

**主用户**：28–38 岁、自己下单的 A 股个人投资者。年交易 20–80 次，持仓 3–15 只，单笔 1–10 万。
典型状态是「有复盘意愿，但手里的复盘只有一张盈亏表」——能说出「我为什么买」，说不出「什么情况下我该认错」。

**非目标用户**：机构/量化（已有系统化归因）、纯新手（只想知道买什么）。这两类会把这个产品拉偏。

| 场景 | 用户处境 | 产品做什么 | 产出 |
|---|---|---|---|
| 单笔深度复盘 | 赚了 13% 就跑，之后又涨 15% | 锁定卖出时点，只呈现当天可见信息，检验「当时写下的规则有没有被触发」 | 是执行问题，还是规则本身没写 |
| 一组交易找模式 | 一年几十笔，不知道亏损的共同点 | 按规则库聚合命中项（追涨、无证伪条件、仓位过重） | 个人错误词典 Top3 |
| 下一次决策前 | — | 建仓前调出同类历史复盘与待勾选清单 | 决策日志建档 |

## 核心机制：时点防火墙

这是产品最核心的一件事。**不是给事后信息打个标签，而是让它进不了「当时的我」这个视图。**

| 时间精度 | 判定规则 | 结果 |
|---|---|---|
| 毫秒 | `publish_time ≤ cutoff` | 可见；反之判为事后 |
| 日期 | 整日已过 | 可见 |
| 日期 | 未到该日 | 事后 |
| 日期 | **与决策同一天** | **不确定** —— 分不清盘前盘后，既不算可见也不算事后 |
| 无时间 | — | 不可见，单独列出 |

日 K 线的收盘价按当日 15:00 记为可见时点。所以 10:23 买入的决策，**当天的收盘价属于事后信息**，
界面上会出现一张说明卡解释这件事，而不是让时间线莫名空一块。

另有三道保险：

1. `partitionByCutoff()` 在查询层分组，事后证据根本不进 `visible` 数组；
2. `guardNoFutureLeak()` 在出口复查，只要混进一条非可见证据就直接抛错，不静默渲染；
3. 归因函数入口也调用同一道护栏 —— 护栏只在 UI 层是不够的。

## AI 的角色

**做四件事**（传统代码做不了的）：

1. 非结构化 → 结构化：把「存储涨价周期延续，中报后会有第二波」抽成假设台账字段
2. 追问：陈述里缺「什么情况下你认错」时，针对性追问而不是给空模板
3. 证据排序：几十个交易日几百条资讯里挑出与陈述相关的几条（iFinD 语义检索）
4. 叙述生成：把规则命中的硬证据写成读得下去的中文

**不做三件事**：

1. **不算任何数字** —— β、行业超额、持有交易日、收益分解全部由代码计算
2. **不判定偏差成立** —— 偏差来自规则库，每条有可复算的判定条件
3. **不给结论** —— 不输出涨跌预测、收益承诺、买卖建议

偏差规则示例（`src/lib/bias.ts`）：

| 编码 | 判定条件 |
|---|---|
| `no_falsify_condition` | 证伪条件为空，或为「没想过 / 没有 / 没有专门想过…」类否定式表述 |
| `chase_high` | (建仓价 − 前 20 交易日最高价) / 前 20 交易日最高价 > −3% |
| `hot_rank_driven` | 建仓日在同花顺热榜排名 ≤ 10 |
| `early_exit_no_rule` | 卖出后 10 个交易日内最高收盘 > 卖出价 × 1.10 |
| `concentration` | positionWeight > 40% |
| `hold_loser_past_rule` | 区间亏损 且 持有 > 20 个交易日 且 存在非空证伪条件 |
| `capital_flow_against` | 建仓日龙虎榜净买入 < −5000 万元（方向与当天披露的资金流向相反） |

样本不足时只报「样本不足」，不下结论。

## 数据来源与口径

**扶摇金融数据 API**（`X-api-key`）

| 用途 | 接口 |
|---|---|
| 个股日 K | `GET /api/a-share/prices/historical`（前复权） |
| 指数日 K | `GET /api/a-share-index/prices/historical` ← 注意前缀是 `a-share-index` |
| 交易日历 | `GET /api/a-share/calendar/trading-days`（返回近一年，不支持区间参数） |
| 热榜排名 | `GET /api/a-share/special-data/hot-stock-list-history?date=yyyy-MM-dd` |
| 涨停统计 | `GET /api/a-share/special-data/limit-up-statistics?date=yyyy-MM-dd` |
| 龙虎榜 | `GET /api/a-share/special-data/dragon-tiger-list?date=yyyy-MM-dd` |
| 标的检索 | `GET /api/meta/tickers/search?q=` |

**iFinD MCP**（JSON-RPC over HTTP，仓库自带客户端 `src/lib/providers/ifind.ts`，不依赖本机技能包）

| 用途 | 工具 |
|---|---|
| 公告语义检索 | `news.search_notice` |
| 资讯语义检索 | `news.search_news` |
| 板块区间涨跌 | `index.sector_data` |

### 三个必须记住的口径

1. **`date_ms` 是当日东八区零点**，不是收盘时刻。实测 `1785686400000 → UTC 2026-08-02T16:00Z → 东八区 2026-08-03 00:00`。
   代码里用断言固定了这个假设，上游语义变了会直接抛错，而不是让所有 A 级证据时点整体偏移 15 小时。
2. **iFinD `index_data` 的「月涨跌幅」是月频指标**，同一个月每个交易日返回的值完全相同。
   拿它当日期收益率算 β 会全错 —— β 必须用扶摇指数日 K 回归。
3. **交易日 ≠ 自然日**。`tradingDayGap()` 必须传交易日历，日历覆盖不到区间直接抛
   `CalendarCoverageError`，**不回退自然日**。跨国庆长假时两者差 8 天。

### 收益归因的口径

```
个股区间收益（含双边费用）
  = 市场 β 贡献（β × 基准指数同期收益，β 用建仓前 60 个交易日日收益回归）
  + 行业超额（板块区间收益 − 基准指数同期收益）
  + 执行偏差（实际成交收益 − 按首尾收盘价买入持有的理论收益）
  + 残差
```

先各自四舍五入到两位再由总收益倒推残差，保证**五项相加严格等于总收益**。

残差里既有真实的个股事件驱动，也有噪声。**产品不把它伪装成「个股特质贡献」**，
`idiosyncraticPct` 固定为 0，残差全部记在 `unexplainedPct` 并在界面注明「拆不开就不拆」。

## 已知边界

1. **没有分钟级行情**。决策时点的盘中盘面是空白，界面显式说明，不假装有数据。
2. **iFinD 资讯只到日期粒度**。同日发布的内容无法判断盘前盘后，一律判为「不确定」，不计入归因权重。
3. **热榜与涨停统计来自自然日榜单**，按当日收盘后可获取处理。
4. **个股异动解读接口只支持当日查询**，无法回溯到历史决策日，因此没有接入证据层 ——
   这是接口能力限制，不是漏做（实测 `anomaly-analysis-stock` 传历史日期仍只返回当日结果）。
4. **扶摇 `limit-up-pool` 与 `limit-up-statistics` 存在同日冲突**（实测 2026-10-16：池子 0 家、统计 59 家）。
   产品的做法是两方都保留并互指 `conflictWith`，界面提示「两源不一致，请以原文口径判断」，不静默取其一。
5. **本地 JSON 存储**，单进程可用；多人协作场景需替换 `src/lib/store.ts`。
6. 种子数据里的价格、日期、热榜排名是扶摇真实数据，**用户画像与仓位是构造数据**（题目要求匿名）。

## 未做事项

- **提醒卡只做「建仓前拉取」，没做「主动推送」**：用户不打开 `/plan` 就不会看到清单，缺少定时或事件触发的提醒
- **回检需要用户主动点开 `/decisions`**：不会在到期时发通知，只有首页角标提示「N 条待回检」
- **回检的执行情况是自述**：系统能算价格与阈值，但「你到底有没有照做」只能由本人申报，无法交叉验证
- **没有做 OCR 交割单识别**：数字错一位会污染整条归因，收益不抵风险，优先用 CSV + 逐行校验
- **没有接入分钟线**：决策时点的盘中盘面仍是空白，界面显式说明
- **只支持 A 股**：港股/美股的交易日历、涨跌停、龙虎榜口径都不同，硬接会做出半成品
- **偏差趋势的快照需要手动保存**：不会每天自动打点（本地单机应用没有调度器）
- **提醒卡没有主动推送**：到期只在首页「今日待办」与角标提示，不发通知

## 主链路（六个页面）

| 路径 | 作用 | 对应提交要求 |
|---|---|---|
| `/` | 持仓列表、口径标注、入口 | — |
| `/import` | 交割单 CSV 粘贴 → 字段映射回显 → 逐行错误 → 确认导入 | 收集信息 |
| `/hypothesis/[id]` | 假设台账 6 题，证伪条件为空直接拒绝保存 | 还原决策过程 |
| `/review/[id]?viewpoint=` | 双轨时间线（当时 / 后视镜 / 时点不确定）+ 收益归因 + 偏差卡 + 缺口冲突 + 沉淀 | 对齐时间线 + 区分事前事后 + 结构化归因 |
| `/patterns` | 一组交易的共同点：处置效应、偏差频次、偏差趋势快照、逐笔一览 | 「一组决策」的可复用学习 |
| `/plan` | 建仓前调出历史清单，按标的/板块/通用情境匹配，全部确认才能记录决策 | 沉淀回灌到下一次决策 |
| `/decisions` | 决策回检：自动算后续走势与证伪阈值是否触及，再由用户自述清单执行情况 | 让「学习有效」可被验证 |
